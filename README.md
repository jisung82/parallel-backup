# Parallel Backup

Windows에서 사용하는 GUI 기반 병렬 백업 프로그램입니다.

## 핵심 기능

### 병렬 백업
- 하나의 원본 폴더를 여러 경로에 동시에 백업
- 대상별 병렬도 제한
- 대상 수가 많아도 설정한 worker 수만큼만 동시에 실행

### 이름/스냅샷
- 백업 이름 + 날짜/시간 자동 생성
- 같은 초에 여러 번 실행해도 `_01`, `_02` 식으로 충돌 회피
- 중간 작업은 `.parallel-backup.partial-*` 임시 폴더에 작성
- 검증 성공 후 최종 스냅샷 폴더로 원자적으로 이름 변경

### 증분 백업
- 각 대상 경로의 최근 **검증 완료** 스냅샷을 기준으로 비교
- 변경되지 않은 파일은 선택적으로 하드링크 재사용
- 하드링크가 꺼져 있으면 안전하게 일반 복사
- 이전 버전(v2) manifest도 증분 기준으로 호환

### SHA-256 무결성
- 백업 생성 후 실제 대상 파일을 SHA-256으로 검증
- 누락/변조/복사 오류를 탐지
- 검증 완료된 스냅샷만 이후 증분 백업의 기준으로 사용
- 복구 후에도 SHA-256 재검증

### 빠른 해시 캐시
- `%LOCALAPPDATA%\ParallelBackup\source_cache.json` 사용
- 파일 크기 + 수정 시간 + 변경 시간 메타데이터가 같으면 기존 SHA-256 재사용
- 변경/신규 파일만 해시 재계산
- GUI에서 캐시 사용을 끌 수 있음

### 제외 패턴
쉼표 또는 줄바꿈으로 패턴을 지정할 수 있습니다.

예:

```
.git
Library
Temp
*.log
*.tmp
node_modules
```

파일명뿐 아니라 상대 경로 기준 패턴도 처리합니다.

### 디스크 사전 검사
하드링크로 재사용할 수 있는 파일은 실제 추가 저장공간 계산에서 제외하고, 새로 써야 하는 파일의 크기를 기준으로 여유공간을 검사합니다.

### 보존 정책
대상별로 최신 N개의 **검증 완료** 스냅샷을 유지하고 오래된 스냅샷은 자동 삭제합니다.

### 장애 대응
- 24시간 이상 남아 있는 중간 `.partial` 폴더 자동 정리
- 검증 실패/취소된 백업은 안전한 증분 기준으로 사용하지 않음
- 작업 중 취소 가능

### 설정 프로필
설정은 자동 저장됩니다.

```
%LOCALAPPDATA%\ParallelBackup\profile.json
```

저장 항목:
- 원본
- 백업 이름
- 백업 대상
- 증분/검증/캐시/하드링크 옵션
- 병렬도
- 보존 개수
- 제외 패턴

## 실행

Python 3.10 이상 권장.

```powershell
python app.py
```

외부 Python 패키지는 필요하지 않습니다.

## 예시

원본:

```
C:\ai\uni_mcp
```

이름:

```
uni_mcp
```

대상:

```
D:\Backups
E:\Backups
F:\Backups
```

결과:

```
D:\Backups\uni_mcp_20260921_193000
E:\Backups\uni_mcp_20260921_193000
F:\Backups\uni_mcp_20260921_193000
```

## 권장 설정

대형 개발 프로젝트에는 보통 다음 구성이 적합합니다.

```
증분 백업       ON
SHA-256 검증    ON
빠른 해시 캐시  ON
하드링크 재사용  ON
동시 대상 수    2~4
보존 스냅샷     5~10
```

백업 안정성을 최우선으로 하려면 **하드링크 재사용을 OFF**로 두면 각 스냅샷이 독립적인 일반 파일 복사가 됩니다.

## 주의

- 백업 대상은 원본 폴더 내부에 두지 마세요.
- 하드링크 재사용을 켜면 변경되지 않은 파일은 여러 스냅샷이 같은 파일 내용을 공유합니다. 공간은 절약되지만 백업 스냅샷을 직접 수정하는 용도에는 적합하지 않습니다.
- 중요한 데이터는 서로 다른 물리 드라이브 또는 다른 저장 위치에 복수 백업하는 것을 권장합니다.
